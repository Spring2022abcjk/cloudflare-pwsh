# P3.1 Production Runtime Summary

The P3.1 runtime-first scope is complete. This summary records the outcome of
the [P3 plan](./P3-plan.md), the final [progress log](./P3.1-progress.md), and
the runtime boundary in [architecture](./architecture.md). P3.1 closes the
shared generated-operation transport/runtime gate; it does not close the
separately deferred generated public `PSCmdlet` surface, publishing, or full
real-account behavior.

## Scope and Outcome

P3.1 establishes a shared runtime between declarative operation metadata and
HTTP transport. The dispatcher consumes generated metadata and bound values,
selects serializers/parsers from representations, applies authentication,
handles replayability-aware retries, and executes shared pagination. Raw
OpenAPI remains confined to the normalization layer.

The acceptance status is **complete**: all ten P3.1 acceptance gates have
deterministic mock, static, host, or regression evidence. Real-account behavior
was kept separate and was not used to substitute for mock evidence.

## Confirmed Architecture

- The normalized model and projection preserve method, path, parameter location,
  request/response representations, envelope/parsing mode, multipart part
  metadata, and pagination evidence.
- The generator emits declarative `GeneratedOperationMetadata` records in
  `Generated/Metadata/CfDnsRecordRuntimeMetadata.cs`.
- `GeneratedOperationMetadataAdapter` maps generated metadata into
  `RuntimeOperationMetadata` and `RuntimePaginationMetadata`; it does not parse
  OpenAPI and does not inspect operation IDs to select transport behavior.
- The handwritten DNS client selects generated operation IDs for List, Get,
  Create, Update, Edit, and Delete. It no longer repeats endpoint-specific
  method/path/parameter/representation metadata.
- The dispatcher owns request construction, shared transport invocation,
  response representation selection, parser dispatch, error conversion, retry,
  and pagination integration. Pagination loops remain in shared strategies,
  not in endpoint wrappers.
- DELETE preserves the normalized correction that its declared body is
  effectively absent.

## Implemented Runtime Capabilities

- Transport-neutral `CloudflareRequest` and `CloudflareResponse` contracts with
  `ResponseHeadersRead` transport and end-to-end cancellation.
- Generic path, query, header, request-body, response, envelope, and error
  dispatch.
- JSON Cloudflare-result parsing, raw text parsing, response-owned binary
  streams, no-content responses, and multipart text/binary request parts.
- Shared `SinglePage`, `V4PagePaginationArray`, `V4PagePagination`,
  `CursorPagination`, `CursorPaginationAfter`, and `CursorLimitPagination`
  strategies, including cancellation, empty-page/terminal-page handling, and
  repeated-cursor protection.
- Deterministic retry policy coverage for connection/timeout failures, 408,
  409, 429, 5xx, retry headers, exponential delay, and jitter. Mutation retry
  remains disabled unless an explicit idempotency key and retry-safe declaration
  are present.
- Reusable API Token authentication context.
- Stable `CloudflareApiException` and PowerShell `ErrorRecord` diagnostics,
  including status, stable error ID/category, target object, Cloudflare error
  code/message, safe raw body, request ID, retry count, and preserved inner
  transport/parser exception.

## Still Deferred

The following boundaries remain intentionally unresolved and are not required
to close the ten P3.1 gates:

- Legacy authentication.
- Automatic `Idempotency-Key` generation and complete mutation retry-safety
  policy.
- Full PowerShell binary UX such as `OutFile` and `PassThru`.
- HTTP `2xx` with `success=false` semantics; no behavior was invented.
- Complete DNS real-account behavior until an explicit accessible zone is
  supplied.
- P3.2 generated public `PSCmdlet` migration.
- Publishing and release work.

## Final Decision

P3.1 is complete against its defined ten-gate acceptance contract. The next
work should use the deferred list and the P3.2 plan as explicit boundaries;
none of those deferred items should be represented as completed by this
runtime acceptance.
