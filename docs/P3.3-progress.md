# P3.3 Coverage Expansion Progress

This progress log records the completed discovery slice separately from the
future public-surface expansion. It does not claim full API coverage,
real-account validation, packaging, release, or device/manual acceptance.

## Implemented

- Added `tools/Invoke-P33CoverageDiscovery.ps1`, which calls the existing
  loader, normalizer, correction engine, and projection builder.
- Added a deterministic operation-level classification contract covering
  normalization, corrections, projection conflicts, runtime capability gaps,
  bounded public admission, and manual review.
- Added complete JSON and human-readable Markdown baseline reports under
  `artifacts/p3.3`.
- Added `docs/P3.3-plan.md` with dependencies, report schema, D1 extension
  scope, acceptance gates, correction/model/projection decisions, and stop
  conditions.
- Updated architecture, roadmap, README, and development principles with the
  P3.3 discovery boundary.

## Validated

- Pinned source revision `4.0.0` normalized to `3,407` operations and `66,580`
  schemas.
- All `3,407` operations received exactly one final classification.
- One operation carries an API correction trace; eight operations are in the
  current public surface across five cmdlets.
- The baseline reports `3,382` runtime-ready stage operations, `25` runtime
  capability-gap stage rows, `568` projection conflicts, `10` final
  `UnsupportedRuntimeCapability` classifications, and `617` low-confidence
  manual review operations.
- The selected first expansion family, `d1/database`, contains six
  high-confidence, runtime-ready operations, including the partial-update
  operation.
- Discovery output omits wall-clock values and is intended for byte-stable
  regeneration.
- The P3.3 report schema/count test passed, and two isolated discovery runs
  produced identical JSON/Markdown hashes.
- Coverage freshness now compares fresh JSON/Markdown to both the checked-in
  baseline artifacts and each other, including source/input identity and
  schema/operation counts; negative sourceRevision and count mutations fail
  the gate.
- P3.2 portable input hashing now canonicalizes UTF-8 text line endings;
  projector/generator parity, isolated Release build, mock/runtime smoke, and
  P1--P2.4 regression acceptance all pass across the CRLF/LF boundary.

## D1 bounded implementation slice

- Added `tools/Generate-P33D1Fixture.ps1` to derive the six-operation D1
  normalized fixture from the pinned OpenAPI source and API correction engine.
- Added `overrides/powershell-p33-d1-projection.json` and
  `tools/Project-P33D1Projection.ps1`; the canonical artifact is
  `artifacts/p3.3/CmdletModel.json` and contains four cmdlets, six operations,
  five typed models, and complete runtime metadata.
- Added `tools/Generate-P33D1Source.ps1`; it reuses the capability-driven P3.2
  renderer as a library and emits generated D1 source, models, and metadata.
- Added `tools/P33ModelSchemaParity.ps1`; all five public typed models now bind
  to normalized schema/property sources with explicit request/response
  direction, JSON names, C# types, nullable/presence state, and nested-model
  references. Projector and generator both enforce the binding, and object
  fallbacks are denied unless a future explicit allowlist supplies reason,
  source, and provenance.
- Added the generated D1 cmdlets and exported them from the module. PUT and
  PATCH use separate typed body parameters and the `PartialUpdate` parameter
  set.
- Added `tests/P33D1Projection.Tests.ps1`, `tests/P33D1Smoke.ps1`, and
  `tools/Invoke-P33D1ReadOnlyTests.ps1` for normalized facts, canonical
  contracts, source-boundary review, mock HTTP behavior, and isolated
  reproduction.
- The read-only entry point copies only required files from the current
  worktree, excluding VCS metadata, `bin`, and `obj`, while retaining untracked
  P3.3 inputs. D1 smoke stages the module and Release DLL in a temporary
  directory and never writes the repository module path.
- Added `tools/Invoke-P33D1Compatibility.ps1` and the deterministic
  `artifacts/p3.3/d1-projection-compatibility.{json,md}` report; the existing
  projection compatibility engine exposes the new `PartialUpdate` public
  parameter-set change.
- Extended the normalized model with array-item references and effective
  allOf property resolution; P2 normalized fixtures and compatibility graph
  traversal now retain this information.

## Repair-round validation

- The regenerated baseline is source revision `4.0.0`, with `66,580`
  normalized schemas and `3,407` operations.
- The runtime-ready stage count is `3,382` operations; the runtime-gap stage
  count is `25`; the final `UnsupportedRuntimeCapability` classification count
  is `10`. These counts are intentionally distinct.
- Typed-model negative tests for object fallback, wrong C# type, and wrong JSON
  property name fail as required; canonical projection/source regeneration is
  performed through the projector and shared generator.
- Final ordered gates passed: PowerShell parse; P3.3 model/projection and
  coverage freshness/determinism tests; fixture/projector/generator
  reproduction; D1 mock/runtime smoke; compatibility; default `%TEMP%`
  read-only acceptance; P3.2 read-only acceptance including P1--P2.4; and
  `git diff --check`.
- The four independent review findings in this repair round are closed: model
  schema parity, coverage artifact freshness/document counts, bounded
  read-only staging, and repository-module-safe smoke staging.

## Still Deferred

- Complete real-account, device/manual, packaging, publishing, and release
  evidence.
- Unresolved runtime semantics such as `2xx + success=false`, legacy auth,
  automatic idempotency, and complete mutation retry safety.
