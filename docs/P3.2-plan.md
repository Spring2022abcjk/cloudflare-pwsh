# P3.2 前两个 P1 修复与生成器架构计划

## 目标与边界

本阶段修复两个 P1，并处理其暴露出的生成器架构问题：

1. 公共同名手写函数不能遮蔽生成式 cmdlet。
2. canonical artifact 与生成源码、runtime metadata 之间不能只靠输入哈希或局部字段自证。
3. renderer 的控制流必须由 canonical projection 的能力描述驱动，而不是由五个命令名称或固定的 `Get`/`List`/`Set` 形状驱动。

范围仍限定为五个 P3.2 代表性公共命令：`Get-CfZone`、`Get-CfDnsRecord`、
`New-CfDnsRecord`、`Remove-CfDnsRecord`、`Set-CfDnsRecord`。这不是本阶段的
全量 Cloudflare API emitter，也不改变真实账户、发布和未解决语义问题的验收门槛。

默认不提交、不推送、不修改未授权内容。手写实现保留为模块内部 helper，
用于 parity 和迁移期对照，不再作为公共入口。

## 数据链路与 canonical artifact

受控链路是：

`normalized model + projection policy -> canonical projection artifact -> generated source -> runtime metadata/dispatcher -> mock HTTP`

`tools/Project-P32Projection.ps1` 是 projection 的唯一入口。它读取 normalized
DNS/zone model、P2.3 zone projection、PowerShell projection policy 和 P3.2
capability policy，调用纯投影构建函数，生成唯一的
`artifacts/p3.2/CmdletModel.json`。该文件是 canonical public projection，生成器
不能反向创建或覆盖它。

artifact v3 记录完整公共语义：cmdlet/class、operation、HTTP method/path、
parameter set、参数 API binding、类型、必填性、位置、pipeline、默认值、null
policy、alias、body serialization、ShouldProcess、输出策略、help，以及 request
representation、multipart parts、response representation、envelope/parsing 和
pagination 的全部字段。artifact 同时记录输入文件 SHA-256 和覆盖语义对象的
canonical SHA-256 digest。

`tools/Generate-P32Source.ps1` 只读取 canonical artifact、模板和待校验的
runtime source。它通过 capability-driven renderer 生成参数属性、alias、
parameter-set 分支、body binding、single/paged/none 输出和 ShouldProcess；
公共参数、operation id、method/path、binding、metadata 不在 renderer 中重复声明。

## 生成器契约

生成前必须同时通过：

- 输入文件存在且哈希匹配；
- canonical semantic digest 与重新投影结果匹配；
- 每个 cmdlet/class、parameter set、operation 和参数都有完整映射；
- 每个 canonical 参数都在生成源码中被消费，不能静默丢弃；
- operation id、method/path、request/response/pagination metadata 与 runtime source 一致；
- 生成源码只保留 binding、ShouldProcess、metadata dispatch 和 shared runtime 调用；
- runtime metadata 编译后反射结果与 canonical artifact 一致。

因此，保持 `sourceFiles` 哈希不变而直接修改 artifact 的参数类型、alias、
binding、response envelope 或 pagination 规则，会在 semantic parity 或
source/runtime contract 阶段失败；直接修改生成 runtime source 的 request、
response 或 pagination 字段，也必须失败。

## 公共路由与兼容性

manifest 只导出五个生成式 cmdlet。手写 DNS 实现改为模块作用域 helper，供
parity 测试通过模块内部作用域调用。验收使用普通 `Get-Command` 和普通命令调用，
不使用 `Get-Command -CommandType Cmdlet` 绕过路由。

生成式 DNS 命令以 `DnsRecordId` 为主属性；`Get-CfDnsRecord`、
`Remove-CfDnsRecord`、`Set-CfDnsRecord` 通过 `RecordId` alias 兼容旧脚本，alias
不改变 API path binding。

## 验收与证据边界

测试覆盖普通命令路由、alias、pipeline、parameter set、ShouldProcess/Confirm、
错误映射、request method/path/query/body、`TagAbsent -> tag.absent`、
`IncludeShadowMetadata -> include_shadow_metadata`、完整 runtime metadata、
artifact/source/runtime 三方契约和失败路径。

证据分层记录：

- 静态/生成检查：projection、semantic digest、renderer/source/runtime contract；
- mock/runtime：捕获 HTTP、输出、分页、错误和 WhatIf；
- host：PowerShell 模块加载、普通命令解析和真实命令调用；
- device：本阶段无设备验收；
- real-account：本阶段不自动推定存在；
- manual/release：本阶段不自动推定存在。

mock、host 或构建通过，不等于 real-account、device、发布或完整 SDK 接受。
`2xx + success=false`、真实账户 DNS 证据、完整 retry/idempotency、发布包装和
人工 UX 继续保持未关闭。

## 停止条件

任何输入哈希、semantic digest、参数消费、operation、request/response/pagination
runtime metadata 或生成源码契约失败，生成必须停止。测试或生成产生非预期跟踪
文件变化时，停止验收并记录副作用，不以副作用后的工作树作为成功证据。
