# P4.2 Security & Supply-Chain Review

## Review boundary

This review covers `.github/workflows/p34-ci.yml`,
`.github/workflows/p34-schema-update.yml`,
`.github/actions/p34-windows-baseline/action.yml`, NuGet restore inputs,
schema bootstrap, package inputs, and candidate provenance. It does not grant
real-account, manual UX, remote CI, publishing, or release acceptance.

## Findings

| Area | Finding and control | Status |
| --- | --- | --- |
| Remote CI | The checkout has no configured Git remote and this branch was not pushed, so no GitHub Actions run, job result, artifact digest, or hosted-runner comparison is evidenced here. | **Blocker** for P4.3 entry; **Unverified** in P4.2 |
| Action pinning | `checkout`, `setup-dotnet`, `upload-artifact`, and `download-artifact` use full lowercase commit SHAs with readable version comments. Dependabot is configured for reviewable updates. | **Complete** |
| Workflow permissions | Both workflows explicitly grant only `contents: read`; no job grants write permissions or an id-token. | **Complete** |
| Pull-request trust | Workflows use `pull_request`, not `pull_request_target`; `checkout` uses `persist-credentials: false`; no workflow references `secrets.*` or live/release secret names. Fork PRs therefore do not receive a Cloudflare or Gallery secret from these workflows. | **Complete** |
| P3.5 live credentials | A Cloudflare integration token is not wired into ordinary build, test, coverage, package, or schema-update jobs. Any future P3.5 live job must be separate, read-only where possible, and explicitly scoped. | **Reviewed; separate boundary** |
| P4.2 release credentials | No Gallery API key/token or signing secret is configured. A future publish/sign job must be a separate protected job with its own least-privilege secret access. | **Accepted for this non-publish phase; deferred** |
| Artifact boundary | Compatibility/coverage artifacts are named and downloaded separately; the candidate module contains exactly the four module files; provenance and secret-shaped-value checks run before candidate upload. | **Complete locally; remote unverified** |

| Dynamic remote code | No build script executes a downloaded schema script or arbitrary remote code. CI downloads only the reviewed setup action/runtime inputs and the pinned schema payload. | **Accepted with update review** |
| Package provenance | Candidate metadata binds source commit, schema identity, package/version/assembly identity, gate receipts, input report hashes, module file hashes, and ZIP hash; release-mode checks additionally require a clean worktree. | **Complete in release mode after commit; remote artifact digest unverified** |

| Signing | Authenticode is not assumed to be a blocker. The first release must decide whether module assembly/package signing is Required, Recommended, or Deferred using the policy in `P4.2-release-policy.md`. | **Decision deferred** |

## Secret inventory and access policy

| Secret or credential | Intended owner | Allowed jobs | Artifact rule |
| --- | --- | --- | --- |
| `CF_API_TOKEN` / Cloudflare integration token | Local environment or an explicitly separated P3.5 live job | Never ordinary build/test/package/schema-update jobs | Never write to logs, reports, ZIPs, or receipts |
| Future Gallery API key/token | Protected release/publish job only | No P4.2 job; never pull-request jobs | Never put in package or release-note inputs |
| Future signing key/certificate | Protected signing job or approved local release station | No ordinary CI job | Private key never enters an artifact; signed-file evidence records public identity only |
| `GITHUB_TOKEN` | GitHub Actions platform | Read-only default token in these workflows; checkout credentials are not persisted | Not copied into outputs or artifacts |

## Risk classification

- **Blocker:** remote CI evidence is absent; a private security-reporting
  channel is not configured; Gallery metadata/preflight is not ready; signing
  policy is not finally decided.
- **Must fix:** none identified in the implemented local controls.
- **Should fix:** add a protected publish/sign job and, if desired, artifact
  attestations only after the repository's release authority and permissions
  are defined.
- **Accepted:** no ordinary job secret access, read-only workflow permissions,
  SHA-pinned Actions, locked restore, pinned schema content hash, exact package
  boundary, and local provenance checks.
- **Deferred:** real-account secret job, Gallery publishing, Authenticode,
  artifact attestations/SBOM policy, and remote hosted-runner evidence.
