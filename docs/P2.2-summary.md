# P2.2 Special Transport Normalization Summary

## Scope and Evidence

This stage uses four operations from the pinned `ref/api-schemas/openapi.json` revision:

| Operation | Request | Success response | Purpose |
| --- | --- | --- | --- |
| DNS export | none | `text/plain` | text response |
| DNS import | `multipart/form-data` | JSON | multipart request with schema-defined fields |
| AI Search upload item | `multipart/form-data` | JSON | multipart request with an explicit binary file part |
| AI Search download item content | none | `application/octet-stream` | binary response |

Fixtures are under `fixtures/p2.2/`; semantic snapshots are under `tests/golden/p2.2/`. No live Cloudflare account or upload/download was used.

## Answers to P2.2 Questions

- **Confirmed — RequestRepresentation**: The existing representation model expresses multipart content type and points to an object schema whose properties describe the parts. DNS import has required `file` and optional `proxied`; AI Search upload has required `file`, optional `metadata`, and optional `wait_for_completion`.
- **Confirmed — file schema evidence**: DNS import's pinned schema declares `file` as a string without `format=binary`; the normalizer preserves that absence. AI Search upload explicitly declares `file` as `string` with `format=binary`. The normalizer does not infer binary where the schema does not say so.
- **Confirmed — ResponseRepresentation**: The existing model expresses `text/plain`, `application/octet-stream`, and JSON response cases with their schemas and status selectors.
- **Confirmed — Content-Type**: The pinned media types are preserved exactly in request and response representations.
- **Confirmed — EnvelopePolicy**: JSON success responses use `CloudflareResult`; non-JSON success responses use `Raw`; JSON 4xx/5xx responses use `ErrorEnvelope`.
- **Confirmed — ParsingMode**: The existing `Json`, `Text`, and `Binary` modes cover these operations.
- **Decision — model**: No new normalized-model fields were required for P2.2. The existing request/response representation model is sufficient to describe the contract.
- **Decision — runtime**: The production runtime is not extended in this stage. Multipart body construction, raw text return, binary streaming, output ownership, and size limits require separate runtime tests and implementation.

## Normalizer Changes

- Non-JSON response representations are now `Raw` instead of being incorrectly treated as Cloudflare JSON envelopes.
- Exact 4xx/5xx response statuses now receive `ErrorEnvelope` when their content is JSON, matching existing status-class handling.
- Collection semantic inference is restricted to operation ids ending in `-get`, preventing a download operation such as `...get-item-content` from becoming `List` merely because its path ends in a literal segment.

## API Corrections Added

- **Confirmed**: No P2.2 API correction was added. These are direct pinned-schema interpretations, not observed-wrapper corrections.
- **Unresolved**: Whether every multipart operation's declared fields and file encoding match all official SDK wrappers remains outside this schema-only stage.

## Runtime Assessment

- **Confirmed**: The model can describe the transport contracts without endpoint-specific emitter logic.
- **Deferred**: The current `CloudflareClient.SendAsync` handles JSON/envelopes and does not yet provide a production raw-text, binary-stream, or multipart request API. P2.2 intentionally does not claim those transports execute successfully.
- **Deferred**: Retry of replayable multipart bodies, cancellation during streaming, content-length/size policy, temporary-file policy, and PowerShell output types need dedicated runtime design and mock HTTP tests.

## Still Unresolved

- Production multipart/text/binary runtime support and streaming behavior.
- Official-wrapper behavior comparison for each selected transport.
- HTTP 2xx with `success=false` semantics.
- Retry/idempotency, legacy authentication, complete pagination strategies, full help, packaging, publishing, and generated binary cmdlet decisions.
