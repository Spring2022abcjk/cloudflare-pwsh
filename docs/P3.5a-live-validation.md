## DNS export contract drift

The current P3.5a run reached the export endpoint, but the selected zone
returned an authorization failure rather than a successful export. The finding
therefore remains **E. still insufficient evidence** for media-type
classification.

The evidence chain is:

| Source | Observation |
| --- | --- |
| Pinned normalized operation | `GET /zones/{zone_id}/dns_records/export`, `text/plain`, raw text parsing in `fixtures/p2.2/dns-export/operations/dns-records-for-a-zone-export-dns-records.json` |
| Pinned OpenAPI | `ref/api-schemas/openapi.json` records `text/plain` for the `200` response at `/zones/{zone_id}/dns_records/export` and labels the operation as requiring DNS Read. |
| Historical Phase 0 live observation | HTTP 200, `application/octet-stream; charset=UTF-8`, and 8,933 UTF-8 bytes observed in memory only using the old account-scoped credential. This is not current P3.5a evidence. |
| Current P3.5a run | HTTP 403, `application/json`, 215 bytes, provider code `10000`; the response was not treated as an export representation. |

The next safe probe should be performed only after the DNS read permission or
zone association is clarified. It should capture only HTTP status, Content-Type,
Content-Length when present, body byte length, strict UTF-8 validity, and
boolean DNS export shape indicators. It should not persist the export body.
Cloudflare documents this as the read-only
[DNS records export method](https://developers.cloudflare.com/api/resources/dns/subresources/records/methods/export/)
and describes the broader export/import workflow in its
[DNS import/export guide](https://developers.cloudflare.com/dns/manage-dns-records/how-to/import-and-export/).

No correction, normalizer, runtime, or public API change is recommended from
the current evidence. The live 403 is an access finding, not proof that the
historical `application/octet-stream` observation was or was not a compatible
successful export representation. The A/B/C/D classification must wait for a
successful export response with the dedicated scope.

## Secret-handling rules

- Read only the three dedicated environment variables; never fall back to old
  credential names.
- Never accept the token on the command line or write it to a script, repo,
  transcript, exception message, test fixture, or artifact.
- Do not write account/zone IDs, domains, record IDs/names/values, raw DNS
  export, or full API responses.
- Keep any selected record ID in process memory only.
- Emit counts, booleans, status codes, media-type metadata, byte lengths,
  generic error metadata, timing, and passive rate-limit headers only.
- If configuration or candidate provenance is missing, make zero live calls.

