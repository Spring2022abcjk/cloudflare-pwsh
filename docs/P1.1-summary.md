# P1.1 DNS Vertical Slice Summary

长期架构边界与后续原则见 [architecture](./architecture.md)、[roadmap](./roadmap.md) 和 [development principles](./development-principles.md)。

## Confirmed

- The normalized model keeps response envelope policy on `ApiResponseRepresentation`, not `ApiOperation`.
- Six DNS operation fixtures are present: create, list, get, update, edit, delete.
- DNS DELETE preserves the declared request-body contract and records the observed wrapper correction that the effective request has no body.
- `A`, `MX`, `CAA`, `HTTPS`, and `SVCB` are represented as typed union variants with a single-value `type` discriminator.
- `zone_id` and `dns_record_id` are resource bindings, not a single scope enum.
- PowerShell projection merges PUT and PATCH into the `Set-CfDnsRecord` prototype with `Replace` and `Edit` parameter sets.

## Implemented

- `docs/normalized-and-powershell-model.md` revised with response cases, multiple request representations, presence/null rules, structured serialization, resource bindings, and semantic provenance.
- `overrides/api-corrections.yaml` and `overrides/powershell-projection.yaml` are separate and consumed by the projection script.
- `tools/Generate-DnsSource.ps1` reads only normalized fixtures plus overrides, applies the DELETE correction, emits `artifacts/projection/CmdletModel.json`, and generates deterministic C# source.
- Minimal .NET runtime supports Bearer auth, base URL, GET/POST/PUT/PATCH/DELETE, JSON, Cloudflare result envelopes, cancellation, query serialization, V4 page-array pagination, and stable `CloudflareApiException` fields.
- PowerShell module exports `Get-CfDnsRecord`, `New-CfDnsRecord`, `Remove-CfDnsRecord`, and `Set-CfDnsRecord`.
- Generated models and operation metadata are compiled; module smoke imports the compiled assembly and invokes mock HTTP calls.
- Golden snapshots cover generated models, operation metadata, and the four public cmdlet projections.
- Contract tests cover scalar/repeat/dotted query encoding, path substitution, discriminator/body output, omitted versus explicit null, pagination to empty page, PUT/PATCH, all requested HTTP statuses, and transport failure.
- `tests/ModuleSmoke.ps1` verifies typed pipeline output, mock request capture, no DELETE body, and stable PowerShell `ErrorRecord` identity.

## Prototype Decision

- The first public surface uses semantic verbs. A primitive is an invocation-to-operation binding, not an `Invoke-*` naming rule.
- DNS unions default to typed input/hashtable body projection rather than one parameter set per variant.
- List output is item-oriented and automatically requests pages until an empty result page.
- Generated C# is the compiled model/operation metadata boundary; the PowerShell module provides the initial ergonomic surface while the cmdlet projection stabilizes.

> P1.1.5 and P1.2 supersede the prototype limitations below where noted; this document remains the historical P1.1 baseline.

## Remaining Unresolved

- The meaning of an HTTP 2xx response with `success: false` remains unresolved and is intentionally not asserted.
- Production retry/idempotency policy, all pagination strategies, multipart/binary/streaming response modes, legacy authentication, and full help generation are not proven by P1.1.
- The typed input surface is intentionally minimal; explicit null is proven at the JSON contract boundary but not yet exposed as a full presence-aware generated input class.

## Deferred to P1.2

- OpenAPI loader and `$ref` resolver.
- Parameter/request/response normalization from the complete Cloudflare document.
- `oneOf`/`anyOf`/`allOf`, discriminator, pagination, and resource detection from OpenAPI.
- Applying API corrections to generated normalized output and structural diffing generated DNS fixtures against these handwritten fixtures.

## Reproduction

```powershell
pwsh -NoLogo -NoProfile -File .\tools\Invoke-P1Tests.ps1
```

All HTTP assertions use mock handlers; no Cloudflare account or live API call is required.
