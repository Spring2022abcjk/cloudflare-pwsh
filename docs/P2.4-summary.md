# P2.4 Schema Evolution and Compatibility Summary

## Scope

P2.4 adds a typed compatibility engine over old and new normalized API models. It compares semantic operations, scope bindings, parameters, request/response contracts, pagination, schema properties, enums, unions, discriminators, and the PowerShell projection. It does not compare raw OpenAPI text as a compatibility decision and it does not expand the binary cmdlet rollout.

## Confirmed

- `ApiChange` carries a typed change kind, resource/operation/schema identity, path, old/new values, evidence, and independent API, SDK, and PowerShell impact classifications, including explicit zero-count `Unknown` buckets.
- Operation changes cover add/remove, method/path/resource, semantic kind, scope binding, primary resource ID classification, request-body requiredness/presence/representations, pagination strategy/fields/rules, parameters, and response status/content/parsing/envelope/result/error behavior.
- Schema changes distinguish request and response reachability, including query/path/header parameters, and cover schema add/remove/composition plus property add/remove/requiredness/type/nullability/read-only/write-only/default, enum values, union variants, and discriminator mappings.
- `ProjectionModelBuilder` produces deterministic old/new CmdletModels from normalized documents and `ProjectionCompatibility` compares cmdlet presence, parameter sets, parameters, mandatory membership, pipeline binding, output type, `ShouldProcess`, `ConfirmImpact`, and paging behavior.
- PowerShell canonicalization detects `foo-bar`, `foo_bar`, and `foo.bar` collapsing to `FooBar` and classifies the collision as PowerShell-breaking.
- The real pinned schema revision comparison is deterministic and is captured in [JSON](../artifacts/compatibility/0b726721291ca19bfcc3add9e3c2b3f57b9d94e6-to-28bfb054e5fa106464e9fbbf0ffbf362bc85234d.json) and [Markdown](../artifacts/compatibility/0b726721291ca19bfcc3add9e3c2b3f57b9d94e6-to-28bfb054e5fa106464e9fbbf0ffbf362bc85234d.md). The pinned revision adds `custom_expression` to `abuse-reports_MitigatedEntityType`; the normalized comparison reports the enum addition and the affected `ListMitigations.entity_type` parameter schema change.
- The real projection comparison also stores deterministic old/new CmdletModels and a [projection JSON report](../artifacts/compatibility/projection/0b726721291ca19bfcc3add9e3c2b3f57b9d94e6-to-28bfb054e5fa106464e9fbbf0ffbf362bc85234d.json) with its matching Markdown report.
- Production projects, tests, and the P2.3 experiment now target `net10.0`. The module manifest requires PowerShell 7.6, matching the current host's `System.Management.Automation` assembly.

## Inferred and proposed

- An enum addition is API non-breaking when the server accepts the new value, but it is potentially breaking for closed SDK or PowerShell representations. The report therefore keeps the three impact dimensions separate.
- Compatibility decisions should be made from normalized evidence plus correction traces and projection artifacts. Generated source diffs remain a diagnostic, not the contract comparison.
- A future CI/schema-update job can consume the deterministic JSON report and gate according to the relevant impact dimension without changing the normalizer.

## Unresolved and deferred

- The engine reports normalized contract changes; it does not yet prove live-account behavior or runtime behavior for every generated operation.
- HTTP 2xx responses with `success=false`, full multipart/binary runtime handling, and complete paging strategy support remain unresolved from earlier phases.
- No public generated binary-cmdlet rollout is included in P2.4; the handwritten module remains the runtime reference.
