# P3.3 Public Admission Policy

This policy separates technical projection/runtime readiness from permission to
ship a public PowerShell cmdlet. The canonical gate list is
`overrides/public-admission-policy.json`.

Public admission is explicit-only. An operation is public only when it is
present in the current canonical public `CmdletModel`; a newly deterministic
projection is not automatically exported.

## Current bounded decision

Option B is in force. The formal public surface is the five P3.2 cmdlets from
`artifacts/p3.2/CmdletModel.json`:

```text
Get-CfZone
Get-CfDnsRecord
New-CfDnsRecord
Remove-CfDnsRecord
Set-CfDnsRecord
```

D1 and D2 remain bounded validation slices. Their canonical artifacts,
generated source, typed models, runtime metadata, and mock smoke entry points
remain available for isolated testing, but `Get-CfD1Database`,
`New-CfD1Database`, `Remove-CfD1Database`, `Set-CfD1Database`,
`Get-CfHealthCheck`, `New-CfHealthCheck`, `Remove-CfHealthCheck`, and
`Set-CfHealthCheck` are not formal module exports.

## Enforced parity

`tools/Invoke-P33AdmissionParity.ps1` is the production acceptance consumer of
this policy and is invoked by `tests/ModuleSmoke.ps1`. It treats cmdlet name as
the canonical identity and requires exact equality—both missing and extra
identities fail—among:

```text
canonical admitted CmdletModel
        ↕
P2.4 compatibility surface / coverage public classification
        ↕
generated public source
        ↕
module manifest + static module export list
        ↕
generated MAML help commands
        ↕
runtime module ExportedCmdlets + Get-Command surface
```

The gate stages the release assembly into a temporary module directory before
checking runtime exports, so it cannot pass by inspecting only source text.
Negative mutations cover extra manifest, module-script, generated-source,
artifact, coverage, and help commands.

## Required gates

1. The corrected normalized operation is valid and complete.
2. API corrections are explicit and have no unresolved ambiguity.
3. PowerShell projection is deterministic, with no unresolved name collision.
4. Parameter sets are distinguishable by signature or an explicit
   PowerShell-only discriminator, and the final PowerShell identity is unique.
5. The shared runtime covers method, representations, envelopes/errors,
   pagination, cancellation, and the operation's declared behavior.
6. Typed request/response models preserve schema provenance, type,
   nullability, presence, unions, and known map values.
7. The candidate surface is visible to P2.4 projection compatibility.
8. Public verb/noun/help naming is explicit policy rather than heuristic-only
   inference.
9. Mutation safety is resolved, including `ShouldProcess`, confirmation,
   body/presence, destructive behavior, and any retry/idempotency decision.
10. The operation is explicitly admitted by bounded policy and has complete
    artifact/source/mock parity evidence.
11. The exact public cmdlet identity is present on every enforced export/help/
    compatibility surface.

## Non-admission decisions

Generic scope-key and HTTP-method rules can resolve a projection identity, but
they do not auto-admit an operation. Low-confidence semantic inference remains
`NeedsManualReview`. Normalization success, runtime readiness, generated C#,
or a coverage increase are not public-admission gates by themselves.

Scope resolution validates the generated final PowerShell cmdlet-plus-
parameter-set identity after canonicalization. Raw scope keys such as
`Foo-Bar`, `Foo_Bar`, `foo.bar`, `foo bar`, `FooBar`, and `FOO_BAR` cannot be
used to claim uniqueness when they converge in that final namespace.

Composite scope-plus-method discrimination remains a future architectural
opportunity. It is intentionally not part of this repair because it requires
separate public UX, compatibility, and mutation-safety review.

The unresolved `2xx + success=false`, legacy authentication, automatic
idempotency, complete mutation retry safety, real-account, packaging, and
release boundaries remain outside this policy.
