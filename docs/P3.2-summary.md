# P3.2 Summary — Generated Public PowerShell Surface

## 结论范围

本阶段实现了五个有界代表性公共 cmdlet 的生成式入口：
`Get-CfZone`、`Get-CfDnsRecord`、`New-CfDnsRecord`、`Remove-CfDnsRecord` 和
`Set-CfDnsRecord`（PUT/Replace、PATCH/Edit）。

模块不再导出同名手写函数；手写 DNS 实现保留为 module-internal helper，
用于 parity 和迁移对照。DNS 生成命令以 `DnsRecordId` 为主属性，并通过
`RecordId` alias 保持旧脚本兼容。

## 已实现的两个 P1 与架构修复

- `artifacts/p3.2/CmdletModel.json` 是唯一 canonical public projection，版本 3
  由 `tools/Project-P32Projection.ps1` 从 normalized/projection 输入和 P3.2
  capability policy 生成；`Generate-P32Source.ps1` 不再创建或覆盖 artifact。
- artifact 同时记录输入 SHA-256 和完整 canonical semantic digest。生成前会重新
  投影并比较语义，因此只改 artifact 的 `TagAbsent.type`、alias、binding 或
  output/runtime metadata 也不能绕过检查。
- 生成器使用 capability-driven renderer，公共参数、parameter set、operation
  id、method/path、binding、body、output、ShouldProcess 和 runtime metadata 均从
  artifact 读取，没有固定五命令 renderer 或 `renderKind` 分支。
- `-ValidateOnly` 现在把 artifact/template 的 renderer 内存输出与现有 generated
  C# 做规范化换行后的完整内容和 SHA-256 比较，并对模块 MAML 帮助资源执行同样的
  存在性、内容和 SHA-256 比较；缺失源码、API binding、operation id、body binding
  或 ShouldProcess literal 漂移、ValidateOnly 源码/帮助资源缺失都会失败。普通生成
  模式也会在所有 contract/source/runtime 检查通过后才写入 generated source。
- DNS 和 zone 共用 runtime source contract；它覆盖 operation、HTTP method/path、
  参数 name/location/required、request representation/multipart parts、response
  status/content/envelope/parsing，以及 pagination strategy、request/response fields、
  result/page-info/current/total/next-cursor/has-more/next-page/stop rule。P32Smoke
  对编译后的 `CfDnsRecordRuntimeMetadata` 和 `CfZoneRuntimeMetadata` 都执行逐项
  artifact parity。
- `tests/P32Projection.Tests.ps1` 对 renderer literal 和 zone runtime metadata
  提供隔离负向测试；失败输入不会覆盖工作树。
- `tools/Invoke-P32ReadOnlyTests.ps1` 是独立只读验收入口，在临时项目副本中完成
  canonical projection、generated source/metadata、Release build、P3.2
  mock/runtime smoke 和 P1--P2.4 回归，并比较入口前后的工作树状态。
- `TagAbsent` 绑定 `tag.absent`；`IncludeShadowMetadata` 在 Set 的适用 parameter
  set 中绑定 `include_shadow_metadata`；普通命令调用走生成式 cmdlet。
- `Remove-CfDnsRecord` 的 canonical `outputPolicy` 为 `none`，生成器因此省略
  `[OutputType(...)]`；本地 host 的 `CommandInfo.OutputType` 为空，mock 调用实际
  输出数量为 0。其余 item/single 命令仍报告正确的 typed output。
- 生成器从 canonical help 字段产生相邻模块资源
  `Cloudflare.PowerShell-help.xml`。当前资源提供 command-level synopsis/description；
  parameter help、examples、online help 不在本阶段范围内。

## 证据

- 静态/生成：canonical projection、semantic digest、参数消费、operation 映射、
  source/runtime contract 及负向漂移检查通过。
- mock/runtime：五个命令的 method、path、query、headers、body、输出、分页、
  ErrorRecord、WhatIf 和手写/generated parity 通过；Set 的 Replace/PUT 与
  Edit/PATCH ErrorRecord parity 分别通过，默认值 query 行为也有独立断言。
- host：本地 PowerShell host 中模块加载、普通 `Get-Command` 路由、五个命令的实际
  `Get-Help`，以及当前和隔离临时模块目录的帮助发现均通过；没有单独的外部 host
  部署证据。
- device、real-account、manual、packaging/release：未验证。

## 未关闭风险

mock、host、构建和静态测试不等同于真实 Cloudflare 账户或发布接受。legacy
authentication、自动 Idempotency-Key、完整 mutation retry safety、完整 binary
PowerShell UX，以及 HTTP `2xx + success=false` semantics 仍未关闭；本阶段也不
宣称 device/manual/release 完整验收。
