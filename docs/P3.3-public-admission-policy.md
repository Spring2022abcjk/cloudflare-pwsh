# P3.3 Public Admission Policy

This policy separates technical projection/runtime readiness from permission to
ship a public PowerShell cmdlet. The canonical gate list is
`overrides/public-admission-policy.json`.

Public admission is explicit-only. An operation is public only when it is
present in the current canonical public `CmdletModel`; a newly deterministic
projection is not automatically exported.

## Required gates

1. The corrected normalized operation is valid and complete.
2. API corrections are explicit and have no unresolved ambiguity.
3. PowerShell projection is deterministic, with no unresolved name collision.
4. Parameter sets are distinguishable by signature or an explicit
   PowerShell-only discriminator.
5. The shared runtime covers method, representations, envelopes/errors,
   pagination, cancellation, and the operation's declared behavior.
6. Typed request/response models preserve schema provenance, type,
   nullability, presence, unions, and known map values.
7. The candidate surface is visible to P2.4 projection compatibility.
8. Public verb/noun/help naming is explicit policy rather than heuristic-only
   inference.
9. Mutation safety is resolved, including `ShouldProcess`, confirmation,
   body/presence, destructive behavior, and any retry/idempotency decision.
10. The operation is explicitly admitted by bounded policy and has complete
    artifact/source/mock parity evidence.

## Non-admission decisions

Generic scope-key and HTTP-method rules can resolve a projection identity, but
they do not auto-admit an operation. Low-confidence semantic inference remains
`NeedsManualReview`. Normalization success, runtime readiness, generated C#,
or a coverage increase are not public-admission gates by themselves.

The unresolved `2xx + success=false`, legacy authentication, automatic
idempotency, complete mutation retry safety, real-account, packaging, and
release boundaries remain outside this policy.
