# P1.2 OpenAPI → Normalized Model Summary

## Confirmed from OpenAPI

- The loader reads the pinned Cloudflare OpenAPI JSON document deterministically and records source path and `info.version`.
- Local `$ref` resolution supports schemas, parameters, request bodies, and response objects; source references remain on normalized parameters, schemas, request representations, and response representations.
- DNS normalization reproduced six operation ids, HTTP methods, paths, path/query bindings, request content types, response status selectors, Cloudflare JSON envelope policies, and DNS scope bindings.
- Schema composition is retained as `oneOf`, `anyOf`, and `allOf`; the DNS nested anyOf/oneOf/allOf chain is not flattened to `object`.
- Single-value type enums are detected as discriminator variants. The normalized DNS graph contains A, MX, CAA, HTTPS, SVCB and the remaining variants present in the pinned schema.
- The normalizer recognizes `V4PagePaginationArray` from page/per_page inputs and collection/result-info response evidence; non-paginated responses are represented as `SinglePage`.
- Mini OpenAPI tests confirm path-level parameter inheritance, operation-level override, application/json/multipart/text/binary request representations, exact 200/201/204 selectors, 4XX class selectors, default selectors, text/binary/no-content parsing modes, and deep Account/Namespace/Instance bindings.

## Corrected by API Corrections

- DNS DELETE is normalized with `declaredContract = true` but corrected to `effectivePresence = absent`, with a retained correction trace. The same correction is applied by the C# correction engine and by the PowerShell projection input pipeline.

## Inferred by Normalizer

- Operation semantic kind is inferred from operation id and method with `Source` and `Confidence` provenance.
- Resource paths and scope roles are inferred from path segments and parameter names; these are model facts with provenance, not PowerShell naming decisions.
- Envelope and parsing modes are inferred from response status/content representation; 2xx `success: false` behavior remains intentionally unresolved.

## Projected for PowerShell

- P1.2 normalized DNS output is accepted by the same P1.1.5 projection and generator. The projection regression preserves the golden metadata/model output, so raw OpenAPI still does not enter the emitter.
- `Get-CfDnsRecord`, `New-CfDnsRecord`, `Remove-CfDnsRecord`, and `Set-CfDnsRecord` remain module-layer UX; generated C# remains models/metadata.

## Still Unresolved

- Full production retry/idempotency policy, legacy auth, multipart/binary runtime handling, all pagination strategies, complete help, and 2xx `success: false` semantics.
- Configuration JSON Schema validation and exhaustive OpenAPI edge-case coverage beyond the normalized DNS slice.

## Deferred

- Full Cloudflare cmdlet coverage, module publishing, real-account integration, complete streaming/upload runtime, and production policy behavior remain outside P1.2.
