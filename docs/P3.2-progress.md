# P3.2 Generated Public PowerShell Surface Progress

P3.2 当前实现基于 P3.1 runtime foundation，目标是完成前两个 P1 的修复并
保持五个代表性 cmdlet 的可复现 parity。本文记录实现证据和边界，不宣称
real-account、device、manual、packaging 或 release 完整验收。

## Implemented

- 模块公共入口只导出 `Get-CfZone`、`Get-CfDnsRecord`、`New-CfDnsRecord`、
  `Remove-CfDnsRecord`、`Set-CfDnsRecord` 五个生成式 cmdlet。
- 手写 DNS 实现保留在模块作用域 helper 中，仅用于 parity 和迁移期对照。
- `DnsRecordId` 是生成式 API-facing 属性；Get/Remove/Set DNS 命令保留
  `RecordId` compatibility alias。
- `tools/Project-P32Projection.ps1` 从 normalized model、P2.3 projection、
  PowerShell policy 和 P3.2 capability policy 构建唯一的
  `artifacts/p3.2/CmdletModel.json`。
- canonical artifact 已升级为 v3，包含完整参数/operation/runtime/output/help
  语义、输入文件哈希和 canonical semantic digest。生成器不再写 artifact。
- P3.2 输入文件 hash 通过 `tools/P32Hash.ps1` 对 UTF-8 文本换行做规范化，
  因此 CRLF/LF 工作树不会造成错误的 stale-artifact 失败；projector、generator
  和 canonical artifact 使用同一规则。
- `tools/Generate-P32Source.ps1` 只消费 canonical artifact 和模板；renderer
  根据 `execution`、`parameterSets`、`operationBinding`、body serialization、
  output policy 和 ShouldProcess capability 生成源码，不再维护固定五命令模型。
- 生成器会重新投影并比较 semantic digest，检查参数消费、operation mapping、
  public/runtime 参数、request representation、multipart parts、response
  representation、envelope/parsing、pagination 全字段和生成源码边界。`-ValidateOnly`
  会读取现有 `SourcePath`，将其与当前 renderer 从 artifact/template 生成的内存
  字符串做规范化换行后的完整内容/SHA-256 比较；源码缺失或 literal 漂移都会失败，
  也会对生成的模块 MAML 帮助资源执行同样的存在性、内容和 SHA-256 漂移检查，
  不会把 renderer 输出当作现有源码。
- runtime metadata 的 `NextCursorPath`、`HasMorePath` 现在由 DNS/zone runtime
  源码生成器完整发出，并进入统一的 DNS/zone source contract 与编译后 runtime
  parity 检查；校验覆盖 operation、HTTP、参数、request/response representation、
  multipart parts、envelope/parsing 和 pagination 全字段。
- `tests/P32Projection.Tests.ps1` 包含隔离临时文件中的 renderer API binding、
  operation id、body/ShouldProcess literal 漂移、ValidateOnly 源码缺失，以及 zone
  method/path、response envelope/parsing、pagination path/stop rule 负向用例。
- `tools/Invoke-P32ReadOnlyTests.ps1` 提供独立只读验收入口：复制隔离项目副本，
  在临时目录重新投影、生成、编译、运行 P3.2 mock/runtime smoke 和 P1--P2.4
  回归，并在开始/结束比较原工作树 `git status --short`。
- shared `CloudflareCmdletBase` 继续拥有 runtime construction、parameter
  conversion、output、pagination 和稳定错误转换；生成 cmdlet 不复制 HTTP、
  serialization、parsing、retry、paging loop 或 error mapping。
- `outputPolicy = none` 的命令不再生成 `[OutputType(...)]`；因此
  `Remove-CfDnsRecord` 的 canonical artifact、生成源码、实际零输出和
  `CommandInfo.OutputType` 保持一致，`item`/`single` 命令继续生成其 typed
  `OutputType`。
- `tools/Generate-P32Source.ps1` 从 canonical `help.synopsis`/`help.description`
  确定性生成模块旁的 `module/Cloudflare.PowerShell/Cloudflare.PowerShell-help.xml`
  MAML 资源；该资源与静态 `P32CmdletHelpMetadata` 都不是 module 文件中的重复文案。

## Validated

- canonical projection 生成通过，包含 5 个 cmdlet、8 个 operation。
- P3.2 artifact/source/runtime/help parity and the direct read-only acceptance
  gate pass after isolated DNS generation was changed to consume the canonical
  normalized document explicitly. The expected normalized-schema names and
  generator output are reproduced identically across two independent runs;
  the P2.3 projection parity blocker is resolved without overwriting the
  repository artifact during staging.
- Release build 通过，0 warnings、0 errors。
- P3.2 projection contract 通过；直接修改 artifact 的参数类型、response
  envelope 或 pagination stop rule 会失败，即使 source file hashes 未变。
- 直接修改生成 DNS runtime source 的 request representation、response parsing、
  pagination path 或 stop rule 会失败。
- renderer 边界静态检查确认没有 `$cmdletModels`、`renderKind`、固定 operation id
  或命令名分支；参数和 operation 控制流来自 canonical capability metadata。
- P32Smoke 覆盖普通命令 metadata、`TagAbsent`、`IncludeShadowMetadata`、
  alias、pipeline、typed output、paging、WhatIf、Confirm、错误和完整 DNS/zone
  runtime metadata parity；同时确认 Remove 的实际输出数量为 0，且其
  `CommandInfo.OutputType` 为空。
- P3.2 mock parity 覆盖五个命令的 method、path、query、headers、body、输出、
  paging、ErrorRecord 和 no-request WhatIf，手写 helper 仍作为内部基线对照；
  `Set-CfDnsRecord` 的 PUT/Replace 和 PATCH/Edit ErrorRecord parity 均有独立断言。
- 实际本地 PowerShell host 已验证五个命令的 `Get-Help` 均返回 canonical
  synopsis/description；测试同时把资源复制到隔离临时模块目录并从该目录加载。
- 默认值测试同时核对 canonical artifact、生成源码初始化和实际显式默认值 query；
  未绑定的布尔值仍保持 omitted wire 语义，以保留 omitted-vs-explicit-false 边界。
- `tools/Invoke-P32ReadOnlyTests.ps1` 在隔离副本中运行 `Invoke-P24Tests.ps1`；
  工作流入口 `tools/Invoke-P32Tests.ps1` 仍会写入当前工作树，而只读入口不会。
  最终工作树仅允许包含本阶段预期变更，且不提交、不推送。

## Canonical chain

`normalized model + projection policy -> canonical projection artifact -> generated source -> runtime metadata/dispatcher -> mock HTTP`

artifact 是公共投影事实源；生成器是 renderer；runtime metadata 是 transport
和 response/pagination 事实的运行时投影；mock 只证明确定性本地行为，不替代
host、device、real-account 或 manual evidence。

## Scope and acceptance gates

本阶段只覆盖五个有界代表性 cmdlet，不扩展为全量通用 emitter。任何未来扩大
范围都必须先增加对应 normalized/projection policy、canonical artifact、renderer
capability、runtime metadata 和独立失败路径。

## Still Deferred

- legacy authentication；
- automatic `Idempotency-Key` 和完整 mutation retry safety；
- HTTP `2xx` with `success=false` semantics；
- 完整 PowerShell binary UX，例如 `-OutFile`、`-PassThru`；
- 生成 MAML 当前只覆盖 command-level synopsis/description；parameter help、examples
  和 online help 尚未实现或验收；
- complete real-account DNS behavior；
- device-hosted/manual UX acceptance；
- publishing、packaging 和 release work。

上述语义不会因为 mock、构建或静态测试通过而关闭。
