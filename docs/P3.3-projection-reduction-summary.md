## Final-name scope guard

`PowerShellNameCanonicalizer` is shared by projection building and compatibility
collision detection; generated source consumes the canonical artifact rather
than inventing another public-name rule. The scope rule now follows:

```text
raw scope key
  -> candidate parameter-set name
  -> final PowerShell canonical identity
  -> uniqueness validation with cmdlet identity
```

Raw keys that differ only by `-`, `_`, `.`, whitespace, or case cannot produce a
false `ScopeKey` resolution. Zone, Account, and Namespace positive cases still
resolve. Same-scope/same-method cases remain unresolved. P2.4 compatibility
continues to see parameter-set identity changes.
