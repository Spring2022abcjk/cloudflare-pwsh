# P3.3 Projection Conflict Reduction Plan

## Objective

Turn the global P3.3 projection-conflict and manual-review population into an
explainable, deterministic taxonomy; fix only general projection capabilities;
and keep technical readiness separate from public cmdlet admission.

The plan is bounded by the pinned source revision `4.0.0`, the current
normalized model, the shared projection builder, the existing P2.4
compatibility surface, and the P3.2/P3.3 evidence boundaries.

## Baseline and taxonomy

The before population is `3,407` operations, with `568` projection-stage
conflicts and `617` `NeedsManualReview` rows. The taxonomy is emitted by
`tools/Invoke-P33ProjectionReduction.ps1` to
`artifacts/coverage/blocker-taxonomy.{json,md}`. It records category counts,
denominators and percentages, representative operations, resource families,
before/after classifications, evidence, and resolution class.

The observed categories are:

| Category | Before count | Selection |
| --- | ---: | --- |
| `ScopeProjectionAmbiguity` | 458 | Resolve with normalized scope-key parameter-set identity. |
| `MethodVariantParameterSetCollision` | 53 | Resolve with normalized HTTP-method parameter-set identity. |
| `ParameterSetIndistinguishability` | 57 | Keep manual/unsupported; no safe generic discriminator remains. |
| `LowConfidenceSemanticInference` | 617 | Keep manual; method-only semantic inference does not establish public UX. |

The first three percentages use the 568 projection-conflict denominator. The
semantic category uses the 617 manual-review denominator. The populations may
overlap: 77 before-conflict rows were also low-confidence semantic rows.

## Implementation rules

`ProjectionModelBuilder` exposes an opt-in generic disambiguation mode used by
global discovery. It applies these rules in order:

1. Keep an explicit policy parameter set unchanged.
2. For an otherwise colliding cmdlet/semantic set, use distinct normalized
   scope-binding signatures and suffix `By...`.
3. If scope does not distinguish every member, use distinct normalized HTTP
   methods and suffix `ByHttp...`.
4. If neither fact distinguishes every member, retain the collision.

The rules do not inspect Cloudflare product names, operation IDs, or resource
families. They do not add transport/runtime branches, change the normalized
model, degrade typed models, or export public commands.

## Admission policy

`overrides/public-admission-policy.json` is the canonical explicit-only policy.
Normalization, correction, projection, runtime, typed-model, compatibility,
naming, mutation-safety, parity, and bounded-policy gates all remain required.
Projection resolution is therefore a prerequisite and diagnostic result, not
an admission decision.

## Acceptance gates

- deterministic before/after coverage and taxonomy artifacts;
- generic scope and HTTP-method synthetic tests, with an unresolved-ambiguity
  negative test;
- P2.4 compatibility visibility for the changed parameter-set projection;
- explicit admission-policy tests proving no automatic public expansion;
- unchanged operation identity set, schema/source revision, current public
  surface, and manual semantic count;
- existing P1–P3.3 regression, Release build, mock/host, and isolated-read-only
  evidence remains green.

## Stop conditions

Stop this reduction phase if the normalized model cannot express the needed
fact, a resource-specific renderer/runtime branch is required, explicit policy
count starts substituting for a general rule, public UX cannot be reliably
determined, compatibility cannot represent the changed surface, typed/presence
or error/pagination guarantees would be weakened, or any prior regression or
determinism gate fails.
